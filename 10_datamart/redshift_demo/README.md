# Amazon Redshift Sales Data Demo with Text-to-SQL

A demonstration of a star-schema sales mart on Amazon Redshift (RA3) with a
natural-language query interface powered by Amazon Bedrock.

## What's in the box

- **Star schema** — `fact_sales` plus 9 dimension tables, with sample data
  generated by `Faker`.
- **Text-to-SQL API** — Lambda + API Gateway. Calls a Bedrock `TextToSQLAgent`
  first, falls back to Claude Sonnet 4.6 via the Bedrock Messages API.
- **Frontend** — single static HTML file. CORS is enabled on API Gateway, so
  no proxy server is required.
- **Automated deploy** — IAM, S3, Redshift cluster, schema, data load, then a
  separate CloudFormation stack for the text-to-SQL API.

## Prerequisites

- AWS account with permissions for Redshift, S3, IAM, Lambda, API Gateway,
  DynamoDB, Secrets Manager, and Bedrock model access.
- Python 3.9+ (Lambda itself runs on 3.12).
- AWS CLI configured.
- A **Bedrock TextToSQL Agent** created out-of-band (with whatever schema
  knowledge / action group you want it to use). The deploy needs its agent ID
  and alias ID — see "Configure the Bedrock Agent" below.

## Quick start

### 1. Install

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

### 2. Configure the Bedrock Agent

Create a Bedrock Agent in the console for text-to-SQL on this schema, publish
an alias, then export both IDs:

```bash
export BEDROCK_AGENT_ID=XXXXXXXXXX
export BEDROCK_AGENT_ALIAS_ID=YYYYYYYYYY
```

The Lambda fallback (Claude Sonnet 4.6) does not need these — it kicks in if
the agent is unreachable.

### 3. Set the master password

Either supply your own password:

```bash
export MASTER_PASSWORD='YourStrongPassword!'
```

…or omit it and let the deploy generate one and store it in Secrets Manager
(secret name: `redshift-text-to-sql-credentials`).

### 4. Deploy

```bash
./deploy.sh
```

This creates the staging S3 bucket, a least-privilege IAM role scoped to that
bucket, the Redshift cluster, the schema, loads sample data, then deploys the
text-to-SQL CloudFormation stack and uploads the real Lambda code.

The script prints the API Gateway endpoint URL at the end. Paste that URL
into the field at the top of the frontend.

### 5. Open the UI

```bash
./start_demo.sh
# then open http://localhost:8080/
```

## Running tests

```bash
pip install -r requirements-dev.txt
pytest
```

The test suite covers:

- `config.py` — env var precedence, password generator complies with Redshift
  rules, regression tests that prevent re-introducing the default password or
  `publicly_accessible: true` to `config.yaml`.
- `text_to_sql_lambda.py` — request validation, agent invocation, fallback to
  Sonnet 4.6 via the Messages API, session-id pass-through, error handling.

No AWS credentials are needed; all boto3 clients are mocked.

## Security notes

- `config.yaml` does **not** contain a master password. It comes from the
  `MASTER_PASSWORD` env var or is generated and stored in Secrets Manager.
- `redshift.publicly_accessible` defaults to `false`. Flip it only for a
  short-lived demo cluster you can reach from your IP.
- The Redshift IAM role gets an inline policy scoped to the staging bucket
  ARN — not `AmazonS3FullAccess`.
- The Lambda IAM policy is scoped to the specific Bedrock agent alias ARN,
  the Sonnet 4.6 inference profile ARN, the Redshift cluster/db/user, the
  prompt template DynamoDB table, and the credentials secret.
- API Gateway CORS is configured directly; the old `proxy-server.js` has
  been removed.

## Cleanup

```bash
python scripts/cleanup.py
```

Deletes the Redshift cluster, IAM role, and (with prompt) the staging bucket.
The text-to-SQL CloudFormation stack is deleted separately:

```bash
aws cloudformation delete-stack --stack-name text-to-sql-api
```

## Configuration reference

`config.yaml`:

| Path                              | Default              | Notes                                              |
|-----------------------------------|----------------------|----------------------------------------------------|
| `aws.region`                      | `us-east-1`          | Override with `AWS_REGION` env var                  |
| `redshift.cluster_identifier`     | `sales-demo-cluster` | Override with `CLUSTER_IDENTIFIER`                  |
| `redshift.node_type`              | `ra3.4xlarge`        |                                                    |
| `redshift.number_of_nodes`        | `2`                  |                                                    |
| `redshift.master_username`        | `admin`              | Override with `MASTER_USERNAME`                     |
| `redshift.publicly_accessible`    | `false`              | Set to `true` only for short-lived demo clusters    |
| `redshift.encrypted`              | `true`               |                                                    |
| `data_generation.num_sales_records` | `10000`            |                                                    |

Environment variables that override `config.yaml`:
`AWS_REGION`, `CLUSTER_IDENTIFIER`, `DATABASE_NAME`, `MASTER_USERNAME`,
`MASTER_PASSWORD`, `IAM_ROLE_NAME`, `S3_BUCKET_NAME`, `SCHEMA_NAME`,
`BEDROCK_AGENT_ID`, `BEDROCK_AGENT_ALIAS_ID`.

## Troubleshooting

- **`MASTER_PASSWORD env var is required`** — set it, or run via `deploy.sh`
  which generates one for you on the first run.
- **`agent-not-found` errors in Lambda logs** — check `BEDROCK_AGENT_ID` and
  `BEDROCK_AGENT_ALIAS_ID` are correct; the fallback (Sonnet 4.6) should
  still answer queries.
- **`AccessDenied` on `bedrock:InvokeModel`** — your account needs Bedrock
  model access enabled for `anthropic.claude-sonnet-4-6` in the deploy region.
- **Redshift load errors** — check `stl_load_errors` in the Query Editor.

## Architecture

```
User → Frontend → API Gateway → Lambda
                                  │
                                  ├─→ Bedrock Agent (TextToSQLAgent)  ─┐
                                  │                                     │
                                  └─→ [fallback] Bedrock InvokeModel ───┤
                                              (Claude Sonnet 4.6)       │
                                                                        ↓
                                                                   SQL string
                                                                        ↓
                                  Redshift Data API → query result → JSON
```
